Real-world async source

Wait for intent, then load suggestions.

A travel planner fetches a local JSON response only after someone starts typing in the destination field. Focusing an empty field stays idle, and the same source pattern can call an application API without loading data on page start.

Scenario

User goal: find an airport without requesting or exposing unrelated suggestions before entering a query, and recover if the service fails.

Why local JSON? The request, delay, failure, and recovery remain deterministic—no API key, rate limit, personal data, or third-party availability is involved.

Try it

  1. Focus the empty field and confirm the request count remains zero and no suggestions open.
  2. Type ber, greece, or lhr to start the first request.
  3. Type quickly and watch older requests cancel; use Arrow Down, Arrow Up, and Enter while focus stays in the input.
  4. Choose “Fail the next request,” then use the visible retry action to recover.
  5. Type zzzz to reach the no-results state.

    Accessibility notes

    • The visible label and hint exist before JavaScript. Enhancement adds the combobox relationships to the native search input.
    • Loading, result counts, no results, errors, selection, and clearing use one polite status region. The list exposes aria-busy while a request is active.
    • DOM focus stays in the input while aria-activedescendant identifies the active option. Retry deliberately returns focus to the field.
    • minLength: 1 keeps focus-only interaction idle. After typing starts, the async source forwards the plugin’s AbortSignal to both the artificial delay and fetch(), so blur and newer queries cancel stale work.
    • No state relies on color alone. Focus indicators, forced-colors support, narrow reflow, and reduced-motion preferences are preserved by package and demo styles.
    • A production API still needs authorization, privacy controls, server-side limits, localized messages, and content safety appropriate to its data.

    Developer notes

    The root is [data-a11y-autocomplete]. Its input, popup, list, status, clear button, and optional hidden value use the package’s standard child selectors. Import the built JavaScript and CSS from dist, then pass an async source.

    createAutocomplete(root, {
  source: loadDestinations,
  minLength: 1,
  debounceDelay: 300,
  maxResults: 6,
  clearLabel: "Clear destination"
});

async function loadDestinations({ query, signal }) {
  const response = await fetch("./destinations.json", { signal });
  if (!response.ok) throw new Error(`Request failed: ${response.status}`);

  const destinations = await response.json();
  return destinations.filter((item) => matches(item, query));
}

    Limitation: this fixture filters a small downloaded collection in the browser for clarity. For a large dataset, send the encoded query to your own endpoint and return an already filtered, size-limited response.
