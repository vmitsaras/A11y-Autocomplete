        What the package handles

        A small core with explicit behavior.

        The plugin enhances declared markup, manages the combobox interaction, and gives consuming applications control over data, rendering, messages, and validation policy.

        A

        Keyboard and focus

        Arrow keys move the active suggestion while DOM focus stays on the input. Enter selects; Escape closes.

        B

        Status and state

        ARIA state stays synchronized, and the status element reports results, loading, errors, selection, and clearing.

        C

        Async control

        Async sources receive an AbortSignal; stale or out-of-order responses cannot replace current results.

        D

        Lifecycle cleanup

        destroy() removes listeners and restores author-provided DOM and ARIA state. The same instance can initialize again.

        Get started

        Install, declare, initialize.

        The package does not initialize automatically. Import its baseline styles, then create an instance for a declared root.

        1. Install

        Shell 
        npm install a11y-autocomplete

        2. Initialize

        TypeScript / JavaScript 
        import { createAutocomplete } from "a11y-autocomplete";
import "a11y-autocomplete/styles.css";

const root = document.querySelector(
  "[data-a11y-autocomplete]"
);

if (root instanceof HTMLElement) {
  createAutocomplete(root, {
    items: ["Athens", "Berlin", "Lisbon"]
  });
}

        Required markup

        Begin with a real label and text input.

        Place optional help text below the label and nest the empty popup inside the control. The plugin adds combobox and listbox state plus a visual result summary during initialization.

        <div class="a11y-autocomplete" data-a11y-autocomplete>
  <label class="a11y-autocomplete__label" for="city">City</label>
  <p class="a11y-autocomplete__hint" id="city-hint">Type a city name.</p>
  <div class="a11y-autocomplete__control">
    <input class="a11y-autocomplete__input" id="city" type="text" aria-describedby="city-hint" data-autocomplete-input />
    <button class="a11y-autocomplete__clear" type="button" hidden data-autocomplete-clear>Clear</button>
    <div class="a11y-autocomplete__popup" hidden data-autocomplete-popup>
      <ul class="a11y-autocomplete__list" data-autocomplete-list></ul>
    </div>
  </div>
  <div class="a11y-autocomplete__status" role="status" aria-live="polite" data-autocomplete-status></div>
</div>

        Configuration

        Useful options, with conservative defaults.

        These are the main behavior options. Selector overrides, custom filters, message callbacks, and rendering hooks are also available in the public type.

        Option Type Default Purpose
        items Array [] Provides flat or grouped local suggestions.
        source Async function null Loads suggestions with cancellation and stale-response protection.
        minLength Number 1 Sets the query length required before results are prepared.
        openOnFocus Boolean false Refreshes suggestions on focus. Pair with minLength: 0 to browse before typing; an async source may receive an empty query as soon as focus enters.
        maxResults Number 8 Caps flat, grouped, filtered, and async result sets.
        strict Boolean false Requires a non-empty value to match an available suggestion.
        highlightFirst Boolean false Makes the first result active when the popup opens.
        clearOnEscape Boolean false Allows Escape to clear the value when the popup is already closed.
        autoComplete "list" | "none" "list" Chooses query-corresponding or query-independent suggestion behavior.

        For methods, events, selectors, and every option, read the repository API overview or inspect the exported TypeScript types.

        Accessibility behavior

        The interaction is explicit. So are your responsibilities.

        The plugin follows the editable combobox pattern, keeps focus on the input during option navigation, and restores author-provided state on destroy. Automated coverage is evidence, not a claim of complete WCAG conformance.

        Keyboard interaction
        Key Behavior
        Arrow Down / Arrow Up Opens suggestions and moves the active option.
        Enter Selects the active suggestion.
        Escape Closes the popup. An optional second press clears a closed field.
        Tab Continues normal focus navigation and closes or commits a configured blur selection.

        Integration checklist

        • Provide a meaningful visible label or another valid accessible name.
        • Check custom theme colors and focus visibility in the consuming interface.
        • Keep custom option rendering presentational; interactive descendants are rejected.
        • Test localized content, zoom, forced colors, reduced motion, touch, and relevant screen readers.

        Boundaries

        What this package does not decide.

        • It does not provide inline completion, a remote data service, or a required-field policy.
        • With openOnFocus: true and minLength: 0, focusing before typing may send an empty query; remote sources remain responsible for authorization, privacy, request volume, cancellation, appropriate results, and retry behavior.
        • Lifecycle event details can contain the query, value, item, results, error, and instance references; allowlist telemetry fields instead of forwarding complete event payloads.
        • It cannot validate the accessibility of surrounding form flows or colors overridden by a consuming theme.
        • Automated axe and interaction tests do not replace manual assistive-technology testing.
